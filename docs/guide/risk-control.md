# 下载失败与抖音风控排查

「突然下载不了」大多是抖音的风控在起作用，而不是作品没了或者软件坏了。先按报错在下面的表里找到对应情况，按步骤处理；都试过还不行，带上[日志文件](#反馈问题时带上日志)来反馈。

::: tip 先升级到最新版
2026 年 9 月抖音连续收紧了几次风控，每次都对应一个修复版本（见文末[最近的风控变化](#最近的风控变化)）。低于 **v3.2.0** 的版本请先升级，很多问题升级后就没了。
:::

## 按报错查

报错会显示在下载任务的失败信息和「同步日志」里。

| 你看到的                                                                           | 大概原因                                                   | 怎么处理                                                                                             |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `抖音接口返回异常 200：空响应`，或 `没有返回有效 JSON（HTTP 200，响应体 0 字节…）` | 当前登录会话被抖音限制了拉作品列表（资料、详情往往还正常） | [浏览器复位](#浏览器复位)后重新扫码登录；仍不行就[粘贴浏览器里的 Cookie](#手动粘贴浏览器里的-cookie) |
| `没有返回有效 JSON（HTTP 403…Uifid Not Found）`                                    | 旧版本缺少抖音新要求的请求参数                             | 升级到 v3.1.0 及以上                                                                                 |
| `作品详情中未找到作者数据`（用作品链接添加用户时）                                 | 详情接口校验变严，旧版本 Cookie 不完整                     | 升级到 v3.1.1 及以上，再点一次[从浏览器获取](#从浏览器获取)；急用可以改贴作者主页链接                |
| `抖音接口返回 status_code=…，通常是 Cookie 失效或触发风控`                         | Cookie 过期，或账号短时间内请求太多                        | 先[从浏览器获取](#从浏览器获取)；还不行就[浏览器复位](#浏览器复位)                                   |
| `抖音页面未发出可取样的请求，可能是 Cookie 已失效`                                 | 后台用来发请求的抖音页面没能正常加载                       | 检查网络能否打开 douyin.com，然后重新登录                                                            |
| `未配置抖音 Cookie` / `请先配置抖音 Cookie`                                        | 还没登录                                                   | 系统设置 → 账号与接口 → 抖音 Cookie → 从浏览器获取                                                   |
| 点「开始下载」后立刻结束，提示没有新作品，但抖音上明明有更新                       | v3.0.x 及更早版本会把风控拦截误当成「没有新作品」          | 升级；新版本会明确报出上面几种错误之一                                                               |

日志里如果看到 `HTTP 444`、`Access Denied`、`X-TT-System-Error`，说明这台电脑的请求在抖音网关就被拒了，通常是短时间请求太多。软件会自动换一种方式重试，你需要做的是[降低请求频率](#降低请求频率)，过一段时间再试。

## 常用操作

以下入口都在 **系统设置 → 账号与接口 → 抖音 Cookie** 卡片里。

### 从浏览器获取

点卡片右上角的「从浏览器获取」，会打开抖音登录窗口。已经登录过的话直接关掉窗口即可，软件会重新读取一份最新的 Cookie。

适合 Cookie 过期、刚升级完版本需要刷新 Cookie 的情况。它**不会**换一个新的登录会话。

### 浏览器复位

点卡片左下角的「浏览器复位」，确认后会清空登录窗口里的抖音会话、缓存和已保存的 Cookie。之后再点「从浏览器获取」，登录窗口是空白的，需要重新扫码。

当你遇到「重新登录了也没用」的情况，就该用它。原因是：只要登录窗口里还留着旧会话，「从浏览器获取」会一直沿用它，被限制的旧会话永远换不掉。

::: warning 复位后下载会暂停
复位会清掉已保存的 Cookie，重新扫码登录之前，所有下载和自动同步都会失败。
:::

### 手动粘贴浏览器里的 Cookie

如果在软件的登录窗口里登录总是很快被限制，可以用你平时的 Chrome 登录抖音，把它的 Cookie 粘贴进来：

1. 在**同一台电脑**的 Chrome 里打开 [douyin.com](https://www.douyin.com) 并登录
2. 按 F12 打开开发者工具，切到「网络 / Network」面板，刷新页面
3. 点任意一个发往 `www.douyin.com` 的请求，在「请求标头 / Request Headers」里找到 `Cookie`，复制它的完整值
4. 回到软件，粘贴到抖音 Cookie 输入框，点「保存 Cookie」

尽量用同一台电脑上的浏览器：软件发请求时模拟的是这台电脑的环境，换一台电脑拿到的 Cookie 更容易被判定异常。

::: danger Cookie 就是你的登录凭证
拿到 Cookie 的人可以直接以你的身份访问抖音。不要发到群里、截图或贴进 issue；反馈问题时也不需要提供 Cookie。
:::

### 降低请求频率

风控很大程度上看请求量。长期大量下载的账号更容易被限制，被限制后也更容易再次被限制。可以从这几处调低：

- **系统设置**里的「并发下载数」
- **下载任务**里的「并发数」
- **用户管理**里各作者的「同步计划（Cron 表达式）」，把自动同步间隔拉长，不要所有作者同时同步

### 使用代理的用户：抖音域名走直连

开着 Clash、Surge 这类代理（尤其是 TUN / 全局模式）时，抖音的请求可能被转到境外节点，结果是作品列表拿不到或者下载很慢。请在代理规则**最前面**加上直连：

```yaml
- DOMAIN-SUFFIX,douyin.com,DIRECT
- DOMAIN-SUFFIX,douyinvod.com,DIRECT
- DOMAIN-SUFFIX,douyinpic.com,DIRECT
- DOMAIN-SUFFIX,douyinstatic.com,DIRECT
- DOMAIN-SUFFIX,zjcdn.com,DIRECT
- DOMAIN-SUFFIX,bytedance.com,DIRECT
- DOMAIN-SUFFIX,snssdk.com,DIRECT
```

## 反馈问题时带上日志

从 v3.2.0 起，软件会把运行日志写进数据目录。每次启动时如果日志超过 5MB，旧的会改名为 `main.old.log`，重新开始记录：

| 系统    | 日志位置                                          |
| ------- | ------------------------------------------------- |
| Windows | `%APPDATA%\dym\logs\main.log`                     |
| macOS   | `~/Library/Application Support/dym/logs/main.log` |
| Linux   | `~/.config/dym/logs/main.log`                     |

反馈时请附上：

- `main.log`（如果出问题的时间比较早，同目录下的 `main.old.log` 也一起带上）
- 软件版本号，以及出问题的大致时间
- 你做过哪些操作，比如是否复位过、是否刚升级

日志里只记录 Cookie 的长度，不记录内容；请求诊断信息里的 `set-cookie` 也会被去掉，可以放心提供。

## 最近的风控变化

| 版本        | 抖音的变化                                                            | 软件的处理                                                                                       |
| ----------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| v3.2.0      | 在软件登录窗口里登录的会话，会被识别为内嵌浏览器并限制拉作品列表      | 登录窗口对外报告的浏览器信息与真实内核保持一致；修复 v3.1.1 引入的 Cookie 重复问题；日志写入文件 |
| v3.1.1      | 作品详情接口要求更完整的设备参数                                      | Cookie 读取范围补全，请求自动带上设备参数                                                        |
| v3.1.0      | 作品列表、详情等接口开始拦截缺少特定请求头的请求（`Uifid Not Found`） | 补上请求头；被拦截时自动改用内置浏览器页面请求；新增「浏览器复位」                               |
| v3.0.x 之前 | 风控拦截返回的是非标准响应                                            | 旧版会误判为「没有新作品」，已在 v3.1.0 修复                                                     |

抖音的风控随时会变。如果按本页处理后仍然下载不了，而且报错不在上表里，请[提交 issue](https://github.com/Everless321/dYm/issues) 并附上日志。
